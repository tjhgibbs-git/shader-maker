# Fog and sky colour: in-game testing handoff

Updated **2026-11-03**, Minecraft Java **26.3 only**. This handoff covers the new Fog workspace and the change from “biome detection” to an explicit Sky colour context. It supplements [the existing layer/UI handoff](in-game-test-handoff.md). Preserve the substantial unrelated working-tree changes; the new implementation is not represented by HEAD alone.

For subsequent UI review, the refreshed authoring JAR, the passing post-UI verification run and remaining graphics blockers, see [the outstanding-work handoff](fog-sky-outstanding-handoff.md). The UI checklist and initial environment notes below describe the original testing handoff; use that follow-up for current completion status.

## Scope agreed with the author

- Fog colour controls are deliberately excluded. Authored fog consumes the world's resolved native `FogColor`; datapacks may configure environment colours. A datapack is **not required** by exported packs.
- Implemented: distance haze, below-height ground mist, height bands, world-space boxes and spheres; density integration, multiple overlapping media, inward edge fades and optional camera-altitude activation.
- Animated patchy density is **parked**. Future work belongs on a separate experimental branch, suggested name `experiment/animated-fog-density`, after measuring this implementation. No noise implementation or experimental branch was created in this revision.
- Lit fog, sunbeams, shadowed scattering and light transport are **unexplored implementation work deliberately excluded** from this build. Do not add them as a prerequisite for accepting density fog.
- Coverage is explicitly **terrain**. Entities, block entities, particles/precipitation, sky, clouds, items and hand retain native fog. Terrain translucent/OIT shader variants compile, but their actual Minecraft behaviour still needs testing. This is not a full-scene volumetric renderer.
- Exports require no mod, shader loader, client mixin, companion renderer or uniform service. Fabric is used only to author projects. Keep 26.3 pinned; investigating compatibility with other versions is out of scope.

## Authoring/UI checks first

Use the Fabric authoring client for this section. Join a world, then open Shader Maker from the pause screen or press **N**. Capture actual screenshots at **340×220**, **480×270**, **640×360** and larger GUI-unit sizes. The new UI is compiled but has not had an in-game interaction review.

1. Open **Fog…** beside Layers. With no fog, select a template and **+ Add**. Check every shape. Selection uses the previous/next buttons; the header identifies the selected medium/count. No reordering is provided because media add optical depth rather than replacing each other by priority.
2. **Look:** edit strength, clear-near and 50%-transmission distance with both sliders and numeric fields. Numeric entry permits values beyond the slider's common range. Distance haze also offers Linear falloff with start/full-fog endpoints; negative linear starts are valid. Shaped fog stays Natural.
3. **Shape:** edit lower/upper Y for a band, upper Y for ground mist, box centre/size, sphere centre/radius, and inward edge fade. Fields paginate on small screens. Invalid dimensions, reversed bounds, excessive fade, non-finite values and incomplete numeric text must stay visible and leave the last valid project intact.
4. Edits are numeric drafts until **Keep settings**, Apply, Export or a navigation action validates them. Check Revert fields, invalid Back/Escape, valid name changes, field focus, slider drag, tab switching and window resize. Revert discards uncommitted fields. Navigation must not discard an invalid draft silently.
5. **Conditions:** leave all camera-Y fields blank for always-on, or enter minimum/maximum/feather. Clear must remove that activation rule without changing physical shape heights. Sky colour/time/weather conditions are not offered here: the current sky detector executes later than terrain rendering.
6. **Quality:** a soft box/sphere exposes 8/16/32 integration samples. Hard shapes and height profiles report analytic integration. These counts are factual, not performance tiers or frame-rate promises.
7. **Preview:** cycle Final / No authored fog / Density and camera altitude. Larger windows show the specimen, transmission curve and vertical cross section beside settings; smaller windows use Preview. These are labelled simulated, with a fixed specimen fog colour. They do not infer geometry from a reference image.
8. Add, name, duplicate, disable and delete media. Undo/Redo must recover all fog values, disabled settings and names. Apply to game uses the exact compiler resources that Export writes. Use Disable on the main editor to remove the applied preview.
9. Save/load/restart the editor; verify fog survives draft recovery, presets/base-grade edits, curve changes and grade-layer edits. Check v7 fog and v8 custom-sky snapshots. Old v1–v6 projects must continue to load without adding fog or changing existing exact-ID selectors.
10. Switch the main editor to **Command pack** with active fog: export must fail with the Auto-mode explanation. Apply is deliberately an automatic preview. Disable every fog object, or set all strengths to zero, and a grade-only Command export must work again.

## Clean-client fog acceptance

Use an **unmodified vanilla 26.3 client**, with no authoring mod or shader loader. Disable the editor preview and all competing shader packs. Use a disposable world and record the chosen backend/GPU/driver, render distance, transparency option, pack order and relevant logs.

1. Enable `fog-demo-always.zip`. Resource reload must succeed without shader errors. Build a valley/steps and terrain pillars at known distances. View from above Y 78, inside the layer and below Y 62. A ray crossing the band must accumulate fog even when its endpoint surface lies above it. Looking horizontally entirely above the band must not receive authored fog.
2. Test Everywhere Natural with visibility 64 and clear-near 0. Authored transmission is 0.5 over 64 blocks, 0.25 over 128 blocks. **The final image also contains native fog and any post grade**, so do not interpret final RGB as an isolated half-mix without accounting for those stages.
3. Test the ground-mist, hard/soft height-band and linear fixtures separately. Check horizontal/near-horizontal sightlines, long terrain faces, boundary pixels, upward/downward views and camera-inside cases. Ground mist is world-height based; filling enclosed rooms at that height is expected. It does not follow ground contours or infer indoor/outdoor status.
4. Test a box and sphere from outside, entering, inside and exiting. Place terrain behind the volume: its ray should fog only over the segment inside. A ray passing beside the volume must remain unaffected by authored density. Far-coordinate packs require travelling to their stored world-space centres or editing them in the authoring client first; see the embedded snapshot.
5. Test overlapping media and duplicate density. Same-colour optical depths add; changing list order in a fixture must not change output. Fog colours are not independently authored per object.
6. Exercise terrain opaque/cutout/translucent paths, leaves, glass, water surfaces, underwater views and all available transparency modes. Fog RGB work must not alter discard, alpha coverage, depth bounds or transmittance. Inspect edges/halos and objects behind multiple transparent layers. Native shader compilation alone did not validate these cases.
7. Compare mobs, chests/block entities, particles, precipitation, sky, clouds and first-person hand against the terrain. Those categories deliberately receive **native fog only**. Record whether the scoped terrain feature is useful despite visible differences; do not mark full-scene coverage as passing.
8. Test native water/lava/powder-snow, blindness/darkness, boss fog and the chunk/render-distance boundary. The authored medium is applied before native fog; it must not expose unseen chunks or remove native fully fogged surfaces. Air-only activation has no proven discriminator and is not implemented.
9. Test first/third person, fractional camera motion, negative coordinates, far coordinates, changing FOV, view bobbing, hurt/portal transforms, resizing, resource reload and dimension changes. Local placements must stay world anchored.
10. Change native fog colour using your own datapack environment attributes. The authored medium should follow the resolved native colour with no resource reload needed to track world changes. There is no fog-colour picker or private runtime input.
11. Disable/remove the pack; native rendering must return. Test pack priority against another terrain override. Enable fog and sky colour together in a **single authored project** to validate their composition; enabling multiple automatic test packs competes for `minecraft:end_of_frame` and is not a valid combined test.
12. Repeat on OpenGL and Vulkan. Measure frame times versus no authored fog for one band, overlapping analytic volumes and a soft box/sphere at 8/16/32 samples. Record hardware and scene coverage; do not invent performance claims from the software-raster harness.

## Sky colour and datapack signalling acceptance

In the authoring client, open a grade layer's **Conditions → Sky colour → Choose sky colour…**. Vanilla-biome buttons select colours, not identities. Hover and page the shared-name list to inspect every stock member. Set a custom `#RRGGBB`, then Use sky colour and Save conditions. A legacy exact-ID selector requires the explicitly labelled conversion action; Cancel must retain its IDs.

The Layers image preview accepts `#RRGGBB` as its simulated sky input, or a vanilla biome ID as a shortcut. Test custom signal, wrong hue, darkness and brightness-scaled matching input. The compiler normalizes RGB by the largest channel, uses a distance tolerance of 0.001 in that normalized space and rejects peak brightness below 0.06. Integer RGB shortcuts do not guarantee every rounded dim colour stays within that tolerance. Same-hue signals cannot encode different locations by brightness alone.

For the **clean-client** test, enable only `custom-sky-always.zip`. In a disposable test world's datapack, supply `minecraft:visual/sky_color` as `#ff8040` through a biome/dimension/timeline under your control. This is ordinary world data supplied by the author's datapack, not a new shader API or a bundled dependency. In daylight, with enough unobstructed sky, the grade should double scene exposure. Another hue should leave it neutral. Do not use an unrelated colour-changing resource pack that replaces the core sky shader.

Test sky blending/borders, weather, night, looking down, roof/underground views, immersion, overlays, dimension changes and pack removal. Missing, too-dark, unknown or tied signals should deactivate the condition; no stale location state is retained. Detector requirements remain a 32×32 sampling grid with at least three agreeing unoccluded marked sky samples. The pack does not encode a robust location signal when sky is absent.

Create a project with both stock and custom colours, then more than 16 distinct active hues. Valid mixed palettes must map to the correct layers; excessive palettes and overlapping hue tolerances must block output explicitly. Disabled custom settings remain saved. The persisted `visualBiomeGroup` field and `VisualBiomes` class names are compatibility details; the author-facing concept is Sky colour.

- `FogShaders.java`: pinned terrain templates, relative-coordinate generation, matching GLSL integration and native fog/OIT compositing.

For each failure record the smallest project/fixture, exact coordinates and camera direction, backend/settings, expected/observed behaviour, screenshots and shader/game logs. Fix and rerun the relevant model/native/raster checks before refreshing artifacts. Mark in-game acceptance only after the standalone exported ZIP passes without the editor mod.
